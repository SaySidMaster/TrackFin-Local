Explication des routes API de TrackFin

1. GET /test : Route de test pour vérifier le fonctionnement de l'API. Paramètres requis : Aucun. Réponse JSON : {"message": "API is working"}.

2. POST /register : Enregistre un nouvel utilisateur dans le système. Paramètres requis : Body JSON {"name": string, "email": string, "password": string}. Réponse JSON : {"user": {"id": int, "name": string, "email": string, "role": string, "created_at": string, "updated_at": string}, "token": string}.

3. POST /login : Authentifie un utilisateur existant. Paramètres requis : Body JSON {"email": string, "password": string}. Réponse JSON : {"user": {"id": int, "name": string, "email": string, "role": string, "created_at": string, "updated_at": string}, "token": string}.

4. POST /logout : Déconnecte l'utilisateur authentifié. Paramètres requis : Header Authorization: Bearer {token}. Réponse JSON : {"message": "Logged out successfully"}.

5. GET /user : Récupère les informations de l'utilisateur actuellement authentifié. Paramètres requis : Header Authorization: Bearer {token}. Réponse JSON : {"id": int, "name": string, "email": string, "role": string, "created_at": string, "updated_at": string}.

6. GET /user/{id} : Récupère les informations d'un utilisateur spécifique par son ID (réservé aux admins). Paramètres requis : Header Authorization: Bearer {token}, Param URL id (int). Réponse JSON : {"id": int, "name": string, "email": string, "role": string, "created_at": string, "updated_at": string}.

7. PUT /user/{id} : Met à jour les informations d'un utilisateur spécifique (réservé aux admins). Paramètres requis : Header Authorization: Bearer {token}, Param URL id (int), Body JSON {"name": string, "email": string, "role": string}. Réponse JSON : {"id": int, "name": string, "email": string, "role": string, "created_at": string, "updated_at": string}.

8. GET /users : Liste tous les utilisateurs du système (réservé aux admins). Paramètres requis : Header Authorization: Bearer {token}. Réponse JSON : [{"id": int, "name": string, "email": string, "role": string, "created_at": string, "updated_at": string}, ...].

9. DELETE /user/{id} : Supprime un utilisateur spécifique (réservé aux admins). Paramètres requis : Header Authorization: Bearer {token}, Param URL id (int). Réponse JSON : {"message": "User deleted successfully"}.

10. GET /categories : Liste toutes les catégories disponibles. Paramètres requis : Header Authorization: Bearer {token}. Réponse JSON : [{"id": int, "name": string, "description": string, "created_at": string, "updated_at": string}, ...].

11. GET /categories/{id} : Récupère les détails d'une catégorie spécifique. Paramètres requis : Header Authorization: Bearer {token}, Param URL id (int). Réponse JSON : {"id": int, "name": string, "description": string, "created_at": string, "updated_at": string}.

12. POST /categories : Crée une nouvelle catégorie (réservé aux admins et comptables). Paramètres requis : Header Authorization: Bearer {token}, Body JSON {"name": string, "description": string}. Réponse JSON : {"id": int, "name": string, "description": string, "created_at": string, "updated_at": string}.

13. PUT /categories/{id} : Met à jour une catégorie existante (réservé aux admins et comptables).
